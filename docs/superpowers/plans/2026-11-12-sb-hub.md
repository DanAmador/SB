# sb hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One local server that shows every Claude Code session and its workers on one page, takes the owner's multiple-choice answers in one place, and makes ticket claims race-free.

**Architecture:** `sbhub.py` is one stdlib file: a `Hub` class (state and rules, no I/O but its store file), an HTTP layer over it, and a CLI client. Claude Code reports through a hooks mod that pipes events to `sbhub hook`. Ticket claims are made safe in `sbmap` itself with an exclusive lock file, so they hold with the hub down.

**Tech Stack:** Python 3 standard library only (`http.server`, `threading`, `json`, `urllib`), `unittest`, one static HTML page with inline CSS and JS.

**Spec:** `docs/superpowers/specs/2026-11-12-sb-hub-design.md`. Working reference for behaviour and the page: `spikes/hub/` (throwaway; read it, do not import it; Task 7 deletes it).

## Global Constraints

- Python standard library only; no new dependency, no build step.
- The server binds `127.0.0.1` only. Default port `8765`, overridden by `--port` or `SB_HUB_PORT`.
- Store file: `$SB_HUB_HOME/state.json`, default `~/.sb-hub/`. Tests always set `SB_HUB_HOME` to a temp dir.
- A hook never blocks or fails its session: `sbhub hook` exits 0 on any input and with the hub down, within 2 s.
- The vault stays the record. The hub never writes into the vault.
- Questions carry two to four options and a default that is one of them.
- Tests are `unittest`, run with `python3 -m unittest discover -s tests -q`; all 76 existing tests keep passing.
- Commits: one per task, explicit pathspec (`git commit -m … -- <paths>`). Never push.
- Words shown to the owner follow `skills/sb/SKILL.md` *Plain words*.

## Review Focus

1. Two sessions claim the same ticket in the same instant: exactly one succeeds (Task 6).
2. The hub is not running: hooks, `report` and `ask` neither hang nor fail the agent; `ask` prints its default (Tasks 2, 3).
3. A provider script hangs, crashes or prints non-JSON: the page still loads and shows that provider's error (Task 4).
4. A question nobody answers: the default applies at the deadline and is recorded as decided by default (Tasks 1, 2).
5. A session that died without a `SessionEnd`: it fades after 10 minutes and is dropped after 24 hours, with its workers (Task 1).

### Task 1: The hub's state and rules

**Files:**
- Create: `skills/sb/scripts/sbhub.py`
- Test: `tests/test_hub.py`

**Interfaces:**
- Produces: `class Hub(home: Path, now=time.time)` with
  - `report(d: dict) -> dict`: `d` has `agent` (id, required) and any of `name, project, role ("orchestrator"|"worker"), parent, ticket, state, note, done, total`. Merges non-empty fields into the stored agent and stamps `at`. `state == "gone"` removes the agent and every agent whose `parent` is it. Returns `{"ok": True, "needs_you": bool}` where `needs_you` is true only on the transition into state `needs you` or `blocked`.
  - `lock(key: str, by: str) -> dict`: `{"ok": True}` or `{"ok": False, "held_by": str}`; re-locking by the holder is ok.
  - `unlock(key: str, by: str) -> dict`: only the holder releases.
  - `ask(agent: str, q: str, options: list[str], default: str, wait: float) -> dict`: `{"ok": True, "id": str}`; raises `ValueError` unless `2 <= len(options) <= 4` and `default in options`.
  - `answer(qid: str, answer: str, by: str = "you") -> dict`: raises `ValueError` if `answer` is not one of the options; a second answer does not overwrite the first.
  - `question(qid: str) -> dict`
  - `state() -> dict`: `{"agents", "locks", "questions", "now"}`; before returning, applies every question's default whose `deadline` has passed (`by: "default"`) and drops agents silent for more than 86400 s with their workers.
  - Every mutation saves `home/state.json`; `Hub(home)` loads it if present. All methods are thread-safe.

**Interfaces:**
- Consumes: `Hub` (Task 1).
- Produces:
  - `sbhub.py serve [--port N]`: prints `sb hub on http://127.0.0.1:<port>` and serves `POST /api/report|lock|unlock|ask|answer` (JSON body, the `Hub` method's arguments by name), `GET /api/state`, `GET /api/question/<id>`, `GET /` (the page, Task 5; until then a one-line placeholder). A refused lock is HTTP 409; a `ValueError` is HTTP 400 with `{"ok": false, "error": str}`.
  - `sbhub.py report --agent A [--name N] [--project PATH] [--role R] [--parent A] [--ticket T] [--state S] [--note N] [--done N] [--total N]`: `--project` is made absolute; exits 0 silently, also with the hub down.
  - `sbhub.py lock <key> --by A` / `unlock <key> --by A`: prints `ok`; a refusal exits 1 with `held by <who>` on stderr; hub down exits 2 with `sbhub: not running`.
  - `sbhub.py ask --agent A --q "…" --options "a|b|c" --default a [--wait SECONDS]`: polls once a second, prints the chosen option. At the deadline, or with the hub down, prints the default.
  - `sbhub.py state`: prints `GET /api/state` as JSON; hub down prints `{}` and exits 0.
  - `call(port: int, path: str, data: dict | None = None, timeout: float = 2) -> tuple[int, dict]`, returning `(0, {})` when the hub cannot be reached.
  - On `report` returning `needs_you`, and on every `ask`, the server calls `notify(title: str, text: str)`: one macOS notification through `osascript`, skipped unless `sys.platform == "darwin"` and `SB_HUB_NOTIFY != "0"`.

**Interfaces:**
- Consumes: `call` (Task 2).
- Produces:
  - `event_report(e: dict) -> dict | None`: pure mapping from a hook event to a `report` body.
  - `sbhub.py hook`: reads one JSON event on stdin, posts `event_report(e)` if not `None`, always exits 0.

  The mapping (`sid = e["session_id"]`, `cwd = e["cwd"]`):

  | `hook_event_name` | report |
  |---|---|
  | `SessionStart` | agent `sid`, name `"<cwd folder> <sid[:6]>"`, project `cwd`, role `orchestrator`, state `idle`, note `session started` |
  | `UserPromptSubmit` | same agent, state `working`, note `reading your message` |
  | `PreToolUse` | state `working`, note `"<tool_name>: <detail>"` cut to 90 chars; detail is the first present of `tool_input.description`, `.file_path`, `.pattern`, else empty. With `e["agent_id"]` present the agent is that id, role `worker`, parent `sid` |
  | `Notification` | state `needs you`, note `e["message"]` |
  | `Stop` | state `your turn`, note `finished its turn` |
  | `SubagentStart` | agent `e["agent_id"]`, name `e["agent_type"]`, role `worker`, parent `sid`, state `working`, note `started` |
  | `SubagentStop` | agent `e["agent_id"]`, role `worker`, parent `sid`, state `done`, note `finished` |
  | `SessionEnd` | agent `sid`, state `gone` |
  | anything else | `None` |

  `hooks.json` registers every event in the table, each as `{ "type": "command", "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/../../skills/sb/scripts/sbhub.py\" hook", "timeout": 3 }`, `PreToolUse` with matcher `*`.
