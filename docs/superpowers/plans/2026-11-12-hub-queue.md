# sb hub queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner ticks tickets on one page; the hub orders them and runs each through a headless worker, checks the result in code, and records it, with no orchestrator session.

**Architecture:** `sbmap` gains the facts a queue needs (map properties, a ticket's tier and checks, one JSON listing of every open ticket). The queue's rules are pure functions in a new `sbqueue.py` (classify, order, brief, check). `sbhub.py` holds the queue in its state behind its one lock and runs it from one supervisor thread that starts workers through an injectable launcher, so every test runs a fake worker script and never a model.

**Tech Stack:** Python 3 standard library, `unittest`; the page stays one static HTML file; the MCP face stays `mcp>=2.3,<3` through `uv`.

**Spec:** `docs/superpowers/specs/2026-11-12-hub-queue-design.md` (binding). Context: `docs/superpowers/specs/2026-11-12-sb-hub-design.md`, `skills/sb/reference/hub.md`.

## Global Constraints

- Standard library only in `sbmap.py`, `sbqueue.py`, `sbhub.py`; no build step.
- Only the running hub writes the queue. CLI, page and MCP go through its HTTP API and refuse when it is down.
- The vault is the record of tickets; every vault write goes through `sbmap` (`claim`, `resolve`, `comment`, `set`, `run`). The queue is hub state (`$SB_HUB_HOME/state.json`).
- No test starts a real agent, touches port 8765, `~/.sb-hub`, or the owner's vault: free port, temp `SB_HUB_HOME`, temp `SB_VAULT`, `SB_HUB_NOTIFY=0`, a fake worker script.
- Workers: one per agent and one per repo at a time. Permission mode `auto`. Antigravity is never a default.
- A ticket runs only when: type is `task`, `research` or `prototype`; it has a `Done when`; it has checks (its own or its map's); every blocker is resolved or queued ahead of it.
- Order rule, fixed: after its blockers; then priority S→F; then the ticket that unblocks the most queued or available tickets; then map order.
- Page rules from the hub build hold: no inline handlers, every value escaped, no external resource, plain words, no bare ids.
- `python3 -m unittest discover -s tests -q` passes with pristine output after every task; the MCP tests run with `uv run -q --with "mcp>=2.3,<3" python -m unittest discover -s tests -p "test_hub_mcp.py"`.
- One commit per task by explicit pathspec. Never push. No tree-wide git.

## Review Focus

1. The hub dies mid-ticket: on restart the claimed ticket with no live worker is released and re-queued, and no ticket is ever resolved without its check having passed (Task 5).
2. A worker commits but a check fails, or commits outside its paths: the ticket stays open with the reason, the commit is left in place, and the next ticket of that repo still runs (Task 5).
3. A ticket changes under the queue (resolved by hand, claimed by a live session, a blocker reopened): it is re-read just before it starts and skipped with its new state (Task 5).
4. The agent hits its usage limit: only that agent's tickets wait, the claim is released, and the queue resumes at the reset without the owner (Task 5).
5. Two requests reorder or untick at once, or the page acts on a stale list: the API takes a queue version and refuses a stale write with the current list (Task 4).

### Task 3: The queue's rules, as pure functions

**Files:** Create `skills/sb/scripts/sbqueue.py`; Test `tests/test_queue_rules.py`.

**Interfaces — Consumes:** the ticket dicts of Task 2. **Produces:**
- `key(t) -> str`: `"<map>#<num>"`.
- `classify(t, queued: set[str]) -> tuple[str, str]`: state and plain-words reason, state one of `ready`, `blocked`, `waits for you`, `not ready`, `claimed`. Rules in this order: status claimed → `claimed` (reason: who); type `grilling` or `architecture` → `waits for you`; no Done-when → `not ready` ("no done-when"); no checks → `not ready` ("no check commands"); any `blocked_by_open` not in `queued` → `blocked` ("after <title of the first>"); else `ready`.
- `order(tickets: list, queued: list[str]) -> list[str]`: the queued keys in run order by the Global Constraints' rule; a ticket whose blocker is not resolved and not queued is dropped from the result; a dependency cycle raises `ValueError`.
- `move(order_keys, key, to_index, tickets) -> list[str]`: the owner's drag; the result is clamped so no ticket precedes its blocker.
- `brief(t, map_plain_words: str, run_folder: str, repo: str, branch: str) -> str`: `templates/session-brief.md` filled from the ticket alone (title, why, question, done-when, out, paths, checks), background = the map's plain words; no model-written part; ends with the report path `<run_folder>/<num>.md`.
- `verdict(t, repo, base_sha, run=subprocess.run) -> tuple[bool, str, str|None]`: passed, reason, commit sha. Passes only when a commit after `base_sha` carries the trailer `Ticket: <map>/<num>`, touches only files under the ticket's `paths` (when it has any), and every check command exits 0 in `repo` (each with a 20-minute timeout; the reason names the first failing command and its last 20 output lines).

- [ ] **Step 1: Failing tests**, table-driven with literal ticket dicts: each `classify` rule and their precedence; `order` for (a) a blocker queued after its dependant is moved before it, (b) priority S before C, (c) equal priority: the ticket two others wait on goes first, (d) ties keep `map_order`, (e) an unqueued unresolved blocker drops the dependant, (f) a two-ticket cycle raises; `move` cannot put a ticket above its blocker; `brief` contains the why, the done-when, each path, each check, the report path, and none of `<` placeholders left; `verdict` in a temp git repo: no commit → `(False, "no commit…", None)`; a commit without the trailer → False; a commit touching a file outside `paths` → False naming the file; a failing check → False naming the command; all good → `(True, …, sha)`.
- [ ] **Step 2:** FAIL (no module). **Step 3:** Implement. **Step 4:** Pass + full suite. **Step 5:** Commit `feat: sbqueue, the queue's rules in code (classify, order, brief, verdict)`.

### Task 4: The hub holds the queue and the agents

**Files:** Modify `skills/sb/scripts/sbhub.py`; Test `tests/test_hub_queue.py`.

**Interfaces — Produces** (all `Hub` methods under its one lock; HTTP under `/api/…`, POSTs through the existing Origin/Content-Type/Host gate; CLI commands refuse with exit 2 `sbhub: not running` when the hub is down):
- State keys `queue: {version: int, paused: bool, agent: str|None, items: [ {key, kind: "ticket"|"job", agent: str|None, state: "queued"|"running"|"done"|"failed"|"skipped", note, commit, tries: int, started, ended, …job fields} ]}` and `agents: {name: {kind: "claude"|"agy", dir, model, limited_until: float|None}}`.
- `Hub.agents_scan() -> dict`: Claude configs `~/.claude` and `~/.claude-*` holding credentials (a `.credentials.json` or `.claude.json` with an account; decide from what exists on disk and say which in the docstring) named by folder (`.claude` → `main`, `.claude-personal` → `personal`), plus `agy` when on PATH; merges with, never deletes, hand-edited entries. CLI `sbhub agents [--scan]`.
- `Hub.tickets(run=…) -> list`: `sbmap tickets --json` (cached 15 s, refreshed by the supervisor) with `state`/`reason` from `sbqueue.classify` and `queued: bool`. `GET /api/tickets`.
- `Hub.queue_set(keys: list[str], version: int) -> dict`: replaces the ticket selection (jobs untouched), orders it with `sbqueue.order`, bumps `version`; a stale `version` returns `{"ok": False, "stale": True, "queue": …}` (HTTP 409). `queue_move(key, to_index, version)`, `queue_pause(bool)`, `queue_agent(name)` (unknown agent → `ValueError`), `queue_item_agent(key, name|None)`. Running and finished items are never removed or moved.
- `Hub.state()` adds `queue` and `agents`; the default selection when the queue has never been set is every `ready` ticket (the owner unticks).
- CLI: `sbhub queue` (prints the order with states), `queue add <map> <NNN>…`, `queue rm <map> <NNN>…`, `queue pause|resume`, `queue agent <name>`.

- [ ] **Step 1: Failing tests** (`Hub` direct with a fake `run` returning fixed ticket JSON, and through `HubCase` for the HTTP/CLI paths): default selection = all ready; `queue_set` orders by the rule and bumps the version; a stale version is refused with the current queue; unticking removes only queued items; `queue_agent("nope")` is HTTP 400; an agent named `agy` is never chosen by `agents_scan` as the queue's default; the queue survives a hub restart; CLI with the hub down exits 2.
- [ ] **Step 2–4:** FAIL → implement → pass + full suite. **Step 5:** Commit `feat: the hub holds tonight's ticket queue and the installed agents`.

### Task 5: The supervisor runs the queue

**Files:** Modify `skills/sb/scripts/sbhub.py`; Create `tests/fake_worker.py`; Test `tests/test_hub_runner.py`.

**Interfaces — Consumes:** Tasks 2–4 and Task 1's recorded JSON shape. **Produces:**
- `launch(agent: dict, brief: str, repo: str, model: str, env: dict) -> subprocess.Popen`, the one place that knows the commands: Claude `[claude, "-p", brief, "--permission-mode", "auto", "--model", model, "--output-format", "json"]` with `CLAUDE_CONFIG_DIR=agent["dir"]`; Antigravity `["agy", "-p", brief, "--model", model, "--output-format", "json"]`; `env` adds `SB_HUB_AGENT=<ticket key>`, `SB_HUB_PARENT="queue"`, `SB_HUB_PORT`. Started in its own process group, stdout+stderr to `<run folder>/<num>.log`. `Hub(…, launcher=launch)` is injectable.
- `sbhub hook` reads `SB_HUB_AGENT`/`SB_HUB_PARENT` and reports under that agent id with `role: worker`, that parent, and the ticket's title as `ticket` (the hub fills it): the worker never reports itself.
- `Supervisor(hub).tick()` — one pass, called every 5 s by a daemon thread started in `serve` (and directly by tests): for each agent and repo that is free, take the first `queued` item that may run; re-read the ticket (`sbmap tickets`) and `skip` it with its new state if it is no longer `ready`; `sbmap run <map>` once per map per night for the run folder; `sbmap claim … --by "hub <agent>"`; record `base_sha`; `launch`. For each running item whose process ended or passed its 90-minute limit (kill the group): limit detected in the log (patterns from Task 1's note; a list constant) → set the agent's `limited_until` (the time in the message, else now+3600), release the claim (`sbmap set status=open`), item back to `queued`; else `sbqueue.verdict` → pass: `sbmap resolve --gist <title> --answer "<checks, counts, model, report path>" --commit <sha>`, item `done`; fail with `tries == 0` and tier `sonnet` on a Claude agent: `tries = 1`, model `opus`, the failed reason appended to the brief, back to `queued` at the front; otherwise `sbmap comment` the reason, release the claim, item `failed`.
- Stops: `paused`; three consecutive `failed` items with the same reason class (`no commit`, or the same check command) pause the queue with that note; an agent with `limited_until` in the future starts nothing.
- Recovery at start: any item `running` has no process: release its claim and set it `queued`.
- When the last ticket item ends, append the night's digest (done, failed, skipped, each with ticket title and commit or reason) to each touched map's run board file.

- [ ] **Step 1:** `tests/fake_worker.py`: a script the test launcher runs instead of an agent; by an env var it (a) commits a change with the right trailer inside the paths, (b) commits outside the paths, (c) commits nothing and exits 1, (d) prints a usage-limit line and exits 1, (e) sleeps past the limit.
- [ ] **Step 2: Failing tests**, each with a temp vault holding two real tickets (through `sbmap`), a temp git repo and `Supervisor.tick()` called by hand: (a) → the ticket is resolved in the vault with the commit, item `done`, the next ticket starts on the next tick; (b) → ticket open with a comment naming the file, item `failed`, claim released; (c) on `sonnet` → retried once on `opus` (the launcher saw `--model opus` and the failed reason in the brief), then `failed`; (d) → agent `limited_until` set, claim released, item `queued`, nothing started until the clock passes it; (e) → the process group is killed and the item fails with "ran past 90 minutes" (use a 1 s limit in the test); two queued tickets of one repo never run at once, two repos with two agents do; a ticket resolved by hand while queued is `skipped`; three (c)-style failures pause the queue; a hub restarted with a `running` item re-queues it and releases its claim; the hook with `SB_HUB_AGENT` set reports under that id as a worker.
- [ ] **Step 3–4:** FAIL → implement → pass + full suite (the runner tests must finish in under 20 s). **Step 5:** Commit `feat: the hub runs queued tickets through headless workers and checks them in code`.

### Task 6: Jobs

**Files:** Modify `skills/sb/scripts/sbhub.py`; Test `tests/test_hub_runner.py`.

**Interfaces — Produces:** `Hub.queue_job(project, prompt, agent, model, name) -> dict` and `sbhub queue job --project P --agent A [--model M] [--name N] (--prompt "…" | --prompt-file F)`: a `kind: "job"` item with a `hash` of project+prompt; the same hash within 86400 s is refused naming the earlier item. The supervisor runs a job like a ticket without claim, verdict or retry: exit 0 → `done`, else `failed`; its log and the JSON `result` text are saved at `<vault>/wayfinder/<project folder>/runs/<date>-<name>/` (made with `sbmap run <project> <name>`), and the item carries that path. A job obeys the same one-per-agent and one-per-repo rule and the limit pause.

Also from the spec's stop rules: `Hub.queue_options(stop_at: float|None, final_review: bool, version)` (page: a time field and a tick box). Past `stop_at` the supervisor starts nothing new and marks the rest `skipped` ("past the stop time"), also while an agent waits for its reset. When the last ticket item ends and `final_review` is on, the supervisor adds one job per touched repo on the night's agent with model `opus` and the fixed prompt "Review the commits of tonight's tickets on this branch (`git log --grep '^Ticket: '` since <base sha>) against each ticket's Done when; write findings to the run folder; change no code."

- [ ] Tests first (fake worker): a job's result lands in the run folder a queue with `final_review` gets exactly one review job per repo after its last ticket; past `stop_at` nothing starts; and the item links it; a duplicate within a day is refused, after a day accepted; a limited agent re-queues the job. Then implement, pass, commit `feat: one-off jobs in the hub queue`.
